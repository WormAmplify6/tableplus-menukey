## 🗄️ Database Connection Manager

Keep database environments easy to identify and maintain.

- Organize connections by project and environment.
- Record hostnames, ports, database names, and usernames where appropriate.
- Separate development, staging, and production configurations.
- Document SSL and network requirements.
- Record connection troubleshooting steps.
- Review outdated connection profiles periodically.

**Security note:** Never commit passwords, private keys, access tokens, or production credentials to a public repository.

## 📝 SQL Query Library

Create a searchable collection of useful SQL statements and explanations.

- Organize queries by project and database type.
- Document the purpose of each query.
- Record expected inputs and outputs.
- Maintain reusable filters, joins, and aggregation examples.
- Store test queries separately from production operations.
- Add notes about performance considerations.

Review destructive statements carefully before executing them, particularly `DELETE`, `UPDATE`, `DROP`, and `TRUNCATE`.

## 🧱 Schema & Table Documentation

Maintain clear documentation of database structures.

- Record table names and their purpose.
- Document columns, data types, and constraints.
- Note primary and foreign key relationships.
- Keep index and uniqueness notes.
- Record schema changes over time.
- Maintain an overview of dependencies between tables.

Schema records should be reviewed whenever the application database changes.

## 🔍 Query Planning & Performance Notes

Use structured notes to investigate slow or unexpected queries.

- Record the query's intended purpose.
- Document approximate execution time and test conditions.
- Keep notes about indexes and query plans.
- Record relevant table sizes where available.
- Compare results before and after a change.
- Document performance regressions and possible causes.

Performance observations depend on the database engine, workload, hardware, and testing conditions. The toolkit does not claim to perform automatic query optimization.

## 🔄 Migration & Change Tracking

Document database changes before applying them.

- Maintain a list of pending migrations.
- Record migration descriptions and version identifiers.
- Document dependencies between schema changes.
- Track testing and review status.
- Record rollback plans where applicable.
- Verify backups before high-impact changes.

Use your application's established migration system as the source of truth. Documentation alone does not execute or validate migrations.

## 💾 Backup & Recovery Planner

Keep a clear record of database recovery procedures.

- Document backup schedules and storage locations.
- Record backup completion and verification dates.
- Maintain restore instructions for each environment.
- Track retention requirements.
- Document recovery responsibilities.
- Test restoration procedures in a safe environment.

A backup is only useful if it can be restored. Periodically verify backups and protect them from unauthorized access.

## 🔐 Security & Access Control

Follow responsible database security practices.

- Use separate accounts for different environments.
- Apply least-privilege access.
- Prefer encrypted connections when supported.
- Store credentials in an appropriate password manager or secret store.
- Avoid exposing connection strings in screenshots or logs.
- Review permissions and rotate credentials when necessary.
- Use synthetic or sanitized data for demonstrations and testing.

Never publish sensitive database exports or customer information in a public repository.

## 🐛 Troubleshooting Center

Build a useful record of recurring database issues.

- Document connection failures and error messages.
- Record database engine and client versions.
- Track authentication and permission problems.
- Note network, SSL, and timeout issues.
- Document recent schema or configuration changes.
- Record the resolution and any follow-up tasks.

Remove passwords, tokens, personal information, and confidential data from logs before sharing them.
